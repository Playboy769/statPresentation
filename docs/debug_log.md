# 除錯紀錄

格式依指引附錄 B。全部為 2026-11-23 實際發生的錯誤，原始輸出可由對應 commit 重現。

### D-01　單元測試資料產生了不存在的日期
- **發現**：Agent 跑 `python -m unittest` 時（ERROR）。
- **重現輸入**：`test_duplicates_keep_last_and_drop_missing` 用 `f"2024-02-{d:02d}"` 產生 2 月 1–32 日。
- **預期**：測試重複日期處理。**實際**：`pd.to_datetime` 對 2024-02-30 拋例外。
- **根因**：**測試本身寫錯**，不是被測程式的錯。
- **修正**：改用 `pd.date_range` 產生真實日曆。**重測**：通過。

### D-02　浮點數用「完全相等」比較
- **發現**：`test_wilson_edges` FAIL：`6.9e-18 != 0.0`。
- **根因**：Wilson 下界的公式在 x=0 時得到 ~1e-17 而非精確 0；測試用 `assertEqual` 不恰當。
- **修正**：改 `assertAlmostEqual(places=12)`。程式不改（數值上已是 0）。

### D-03　稀有事件的測試容差設計錯誤（統計層級的錯誤）
- **發現**：`test_exceedance_on_simulated_normal_matches_normal` FAIL：模擬常態資料 k=3 觀察 40 次、
  預期約 54 次，比值 0.74，超出設定的 ±15%。
- **根因**：k=3 預期約 54 次，次數標準差約 √54 ≈ 7.3；±15% 只有約 1.1 個標準差，
  真模型也有約 27% 機率失敗。**這個測試的判準在統計上就是錯的**。
- **修正**：改用「二項檢定不拒絕真模型（p > 0.01）＋Wilson CI 涵蓋理論值」。
  此例 p = 0.056、CI [0.00147, 0.00272] 涵蓋 0.00270。
- **誠實揭露**：判準是看到失敗後才改的。為避免「換種子換到通過」，**種子 20261123 保持不變**；
  新判準由理論（二項分布）決定，不是由這次的結果決定。

### D-04　Yahoo 在非交易日多一根陳舊 K 棒（資料錯誤，整合時發現）
- **發現**：Yahoo × TWSE 交叉驗證，`only_yahoo = 1`、`only_twse = 1`。
- **追查**：TWSE 原始資料 2026-10 從 10/22 直接跳到 10/27；Yahoo 在 10/23 有一根收盤 2385
  （＝TWSE 10/22 收盤）。→ Yahoo 把非交易日補成陳舊價格，會多一筆假的 0% 報酬。
  另一筆：2025-08-01 Yahoo 收盤是 null，TWSE 為 1140。
- **影響**：單筆 0% 報酬對 SD 影響極小（訓練期 n 1699 → 1698；SD 1.6024% → 1.6028%），
  但它是「只用單一來源不會發現」的錯誤，正是多來源整合的價值。
- **修正**：`integrate.drop_non_trading()` 刪除交叉驗證視窗內 TWSE 判定非交易日的 Yahoo 列，數量寫入品質紀錄。
  R 重驗 26/26、單元測試 14/14 通過。
- **剩餘限制**：視窗外（2024-12 以前）的同類問題無法用 TWSE 驗證（只抓 24 個月，避免過量請求）。

### D-05　PowerShell COM 寫入數字失敗
- **發現**：對活頁簿副本寫 `B3 = 250` 時 `Unable to cast System.Int32 to System.String`。
- **根因**：同一個 PowerShell 工作階段先寫字串（B2）再寫整數，COM 型別快取衝突（專案筆記已知問題）。
- **修正**：一律寫字串 `[string]$Period`；活頁簿本身以 `IsNumeric` 轉換。重跑成功。
